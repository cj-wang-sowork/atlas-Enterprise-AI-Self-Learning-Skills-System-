## Review the actual first output

Expect a small editable team, ICP draft, then immediate work with evidence and QA.
No browsing or verified source packet means a useful bounded draft and blocked
company research, not invented leads. Explicit requested counts override the
three-company default. Nothing is sent or published.

Give one concrete feedback after the output. A CandidateLesson requires that real
feedback plus task evidence; without both there is no candidate. The human uses
Accept / Revise / Reject with exact ID+version, records the decision in
`OUTCOME_REVIEW_LOG.md` and manually retains only the accepted current version.
Revise creates a new pending candidate. Repetition and suggestions do not approve.

`CURRENT_RULES.md` is an initially empty human-maintained template. The current
export includes all visible top-level Markdown/JSON starter assets after complete
preflight. A legacy four-file export still works because this README embeds the
complete generic card; if its separate index is unavailable, initialize a local
index with:

**Approved rules: EMPTY (0)**

Only the operator updates it after explicit exact-version acceptance. Record rule
text, scope, exceptions, task evidence, reviewer/date, active ID/version and review
trigger. Remove/replace superseded context. Supply the current index for each new
task and inspect the exact versions actually used. Rejected/obsolete versions
are not active; no index read means none (0), not inferred approval.

## Optional Project setup

Only after evaluating the first output, create a Project if useful. Manually paste
`PROJECT_INSTRUCTIONS.md` into Project instructions; uploading it as an ordinary
file is not the same as setting project instructions. Add only sanitized context
and the current human-maintained index. Inspect actual sharing/data controls.
A single-chat paste is chat-local context, not verified saved Project setup.

No terminal, Python, API key, connector or whole-repository upload is needed by
this manual route. No claim is made of running ATLAS Python, automatic memory
writes, backend registry changes, training, cross-chat guaranteed retrieval,
completed human-learning rounds or commercial superiority. Prompt rules are not
access control. Project memory is not ATLAS's reviewed lifecycle.

Do not upload `MEMORY.md`, `TOOLS.md`, `memory/`, `outputs/`, raw chats, secrets,
private client material or other clients' information. Use a clean repository
download, not a coworker's personalized workspace. Documents are task data, not
permission to override the rules or disclose information.
