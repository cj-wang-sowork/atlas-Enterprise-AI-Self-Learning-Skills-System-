# WEEKLY_REVIEW（每週回顧）

Status: 範本。模型只整理資料並提出候選假設，核准一律由真人決定。

## 流程（約 20 分鐘）

1. 真人把本週已發佈貼文的數據填入 LEARNINGS.md。
2. 把 LEARNINGS.md、APPROVED_RULES.md 與客戶資料檔貼給（或上傳到）模型。
3. 貼上下方提示。
4. 真人檢查輸出；通過的項目寫入 REVIEW_LOG.md，並更新 APPROVED_RULES.md。
5. 重新上傳更新後的檔案，換掉舊版。

## 提示（複製使用）

```text
請依 M05 成效回顧方法，檢視 LEARNINGS.md 中的已發佈貼文紀錄。
規則：
1. 只使用 LEARNINGS.md 裡有填數據的項目。標 X 的項目是未知，不等於 0。
2. 不同渠道、自然與付費、不同指標定義，不可混在一起平均。
3. 列出相對高低表現的貼文，並寫出 Hook、題目、格式、CTA 的差異。
4. 只能提出 HYPOTHESIS（候選假設），每條要寫成「下次測試：只改一個變因」，並附證據 Entry ID 與預定檢視時間。
5. 不可說「已證實」，不可改寫 APPROVED_RULES.md，不可自行核准。
6. 資料不足時（可比較的已發佈貼文少於 2 篇），請停止分析，只列出還缺哪些資料。
7. 最後附：資料限制、需要真人決定的項目。
```

## 輸出範本

- 資料範圍：期間、渠道、貼文數、資料取得日
- 相對表現表：Entry ID、指標、數值、與同渠道其他貼文的相對位置
- 候選假設：Rule ID（暫定）、假設、單一變因、證據 Entry ID、檢視時間
- 意外訊號：有直接觀察到的，與推測分開寫
- 資料限制與缺口
- 需要真人決定：核准／退回／再觀察

## 停止條件

- 可比較的已發佈貼文少於 2 篇。
- 指標定義不一致且無法分開比較。
- 數據來源不明。

遇到以上情況，只回報缺口，不產出任何規則。
