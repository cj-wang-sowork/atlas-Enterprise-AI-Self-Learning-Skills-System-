# Try one marketing task in ChatGPT

This is an ordinary-chat or Project **trial**, not permanent installation. File
reading, ZIP extraction, browsing and code capabilities depend on the actual
account and session. This guide has not by itself verified native account setup.

## One outcome first

Use an authorized brand brief to request one week of content: 7 complete posts,
visual directions, CTAs and a QA checklist. Start with a fictional brand if the
material is private or consent to processing has not been obtained. Never upload
passwords, customer lists, unpublished personal data or privileged client records.

1. From the repository's Releases, download **ATLAS-Marketing-Team-ChatGPT-Project.zip**.
   It is a text workflow package, not the native Plugin ZIP. Match the release
   source and verification notes; do not mix old/new playbooks.
2. In a new ChatGPT conversation, attach that ZIP only if file processing is
   actually available. Send the short request below with your authorized brief.
3. If ChatGPT cannot unpack the ZIP, do not ask it to pretend. Unzip on your device,
   upload **PLAYBOOK.md**, and paste **PROJECT_INSTRUCTIONS.md** into the conversation
   before the task. For repeat work, put those instructions and the playbook into
   a Project instead. These routes do not activate a Python backend or account tools.

## Copy this request

```text
Read PROJECT_INSTRUCTIONS.md and PLAYBOOK.md from the attached ATLAS text package.
If you cannot unpack/read it, tell me exactly which file you need; do not claim
installation or fabricate having read it. Follow the same limitation if an
uploaded reference file is unavailable.

Work in Traditional Chinese. Here is the brand context I authorize you to use:
[Paste only the brand facts, audience, tone and restrictions needed for this task.]

Deliver 7 complete posts for one week, each with its audience/angle, full copy,
visual direction and CTA. Use D1-D7 unless dates/timezone are supplied. State any
reversible assumptions and produce a useful draft before optional setup questions.
Use bundled methods first. Search for new public methods only when the task needs
missing capabilities, fresh evidence or explicitly requests research. Do not
invent sources, claims, analytics, account access, publishing or performance.
Finish with methods actually used, sources/versions, QA and DRAFT — unpublished.
```

Replace the bracketed context; it is not a prepared client record. This request
is an operating instruction, not proof of account isolation or durable memory.

## What the first result should look like

- A short known/assumed/unknown summary, not a ten-question onboarding form.
- Relevant workstreams and applied methods, not biographies or a list of repos.
- Seven usable drafts plus visual directions and CTA, rather than seven titles.
- Citations for checked claims, or an explicit missing-evidence limitation.
- A QA/human-review checklist, DRAFT status and one focused feedback question.

A factual claim is not verified merely because it appears in the brief. If an
external method cannot clear its source/license/environment review, use bundled
methods and report that limit. Public search must never include private briefs.

## Record the actual trial

Keep the actual uploaded release, task, output, setup friction and failures. Note
whether the model actually browsed or ran the helper rather than inferring it
from role labels. Compare the result with the same task/model without the kit
before claiming better quality or time saved. Static tests do not establish native
activation, model adherence, collaboration or business benefit.

For the separate personal localhost web demo, see `native_demo/LOCAL_USE.md` in a full
source checkout. Its Codex-backed response is a web-demo run, not a ChatGPT upload
trial; the two must not be reported as the same acceptance result.
