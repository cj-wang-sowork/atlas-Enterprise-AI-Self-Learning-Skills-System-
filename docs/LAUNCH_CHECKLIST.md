# Public preview checklist

ATLAS is a marketing workflow preview. Describe the delivered outcome and its
limits, not an unmeasured autonomous workforce or a production security product.

## Public copy

Suggested GitHub repository description:

> ATLAS: Open-source marketing workflows for brand-to-content delivery, with task-aware GitHub skill discovery. Preview; platform setup required.

The GitHub About description is repository metadata, not a file. Updating README
cannot update it. An owner/maintainer with the required repository-administration
permission must apply this text separately. Do not leave claims such as “1000+
agent skills”, “five-layer security”, or “Production-ready” in public metadata
unless they are supported by the shipped product and appropriate acceptance.

Keep the repository slug stable; the user-facing title is ATLAS Marketing Team.
Retain historical methodology and upstream licensing without presenting them as
currently connected capabilities. Use one release/version across instructions,
packages and evidence. Do not direct users to an older ZIP as if it had new code.

## First useful result

- One authorized brand brief should lead to a reviewable week of complete copy,
  visual directions, CTAs and QA, not just a team setup or repository directory.
- Test the documented user phrases and common Chinese/English channel aliases.
  A deterministic routing sample is not an overall model-quality score.
- Prefer existing relevant methods for small edits. Discover new public methods
  when a gap, fresh evidence or explicit research warrants it; never disclose
  private brief content to public search.
- A source search is not license/environment approval. Keep provenance, pending
  checks and limitations explicit. Do not auto-execute third-party code.

## Real interface acceptance

Test archive build/integrity, native account upload, model output and human
acceptance separately. For an actual platform trial, preserve the uploaded
release, request, original response, screenshots, tool evidence and failures.
Compare the same task/model without the kit before claiming improved quality,
time saved or willingness to pay. Static contracts are not that comparison.

If the native site is blocked or the account cannot be operated, retain the real
blocker and use the explicitly labelled localhost web demo. A Codex-backed web
result is not a ChatGPT UI upload trial. Do not disguise one as the other.

## Local web-demo boundary

The personal demo binds only to loopback, uses a locally authenticated Codex
session and must not be published as a shared multi-user AI backend. A public
service needs a separate approved metered API integration, authentication, budget
controls, privacy/retention/deletion policy, rate limits and deployment review.
No API credential belongs in client-side HTML, repository files or screenshots.

Only the task and context entered by the user are generation inputs. Do not read
private directories or import other client data. Do not imply account isolation,
continuous synchronization, automatic learning, scheduled work, social posting or
ad-spend authorization from this preview.
